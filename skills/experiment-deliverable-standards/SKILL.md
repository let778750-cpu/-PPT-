# 实验交付质量标准

## 使用时机

在 Phase 6 图表资产、Phase 7 实验报告、Phase 8 PPT、以及最终整理 `项目提交/` 前使用。本 skill 不替代具体写作或绘图 skill，而是为所有交付物提供统一质量门槛。若本标准与其他实验 skill 冲突，以本标准为准。

## 总原则

- 真实可复现优先：报告、PPT、图表中的结论必须来自实验要求、源码、日志、metrics、figures 或 `_workflow` 证据链。
- 指定数据集优先：若实验要求明确点名 MSCOCO、MNIST、CIFAR10、PTB、CamVid 等数据集，最终训练、指标、报告和 PPT 必须使用该指定数据集或其官方可追溯子集；synthetic/mock 数据只能用于 smoke test，不得作为最终结果。
- 草稿文件优先：未获用户审核确认前，必须确认成果位于 `code/workN code/`、`实验报告/实验N/`、`PPT/实验N/`；不得提前同步到 `项目提交/`。
- 最终文件优先：用户确认进入最终提交后，不能只改源目录；必须确认 `项目提交/` 和 `项目提交.zip` 也同步到最新版。
- 视觉结果优先：不能只看 `.tex`、`.pptx` 文本或文件时间；关键 PDF/PPT 页面必须渲染或抽取图片做肉眼检查。
- 发现问题立即修复，不能把“已生成”说成“已达标”。

## 草稿工作区与项目提交边界

实验成果必须先写入非提交工作区，供用户检查：

```text
code/workN code/
实验报告/实验N/
PPT/实验N/
```

`项目提交/` 是最终提交版本目录，只有在用户仔细审核并明确要求同步最终版后，才可以把对应实验复制进去并刷新 `项目提交.zip`。在草稿、迭代、复核阶段，不得直接把新实验写入 `项目提交/`，也不得提前更新最终 zip。

## 项目提交结构

用户确认后，最终提交目录必须采用：

```text
项目提交/
  实验N/
    实验代码/
    实验报告/
    实验PPT/
```

要求：

- `实验代码/` 只保留用户能独立运行并得到正确结果的 Python 代码、必要配置、README、requirements 和小型必要资源。
- `实验报告/` 必须包含最新版 `实验N报告.tex`、`实验N报告.pdf`、`UCASReport.sty`、`figures/`。
- `实验PPT/` 每个实验只保留最新版 `.pptx` 和 `_svg.pptx` 两个文件；删除陈旧、冗余、临时 PPT。
- 仅在用户确认进入最终提交后刷新 `项目提交.zip`，并检查 zip 条目中确实包含新版文件。

## 实验报告标准

报告必须至少包含：

- 一、实验内容
- 二、实验原理
- 三、实验算法设计
- 四、实验结果与分析
- 五、总结与讨论
- 参考文献

写作要求：

- “五、总结与讨论”必须包含 `5.1 实验总结` 和 `5.2 讨论` 两个小模块；两个小模块篇幅应基本相当，较短者原则上不低于较长者的 80%。
- “5.1 实验总结”回顾实验目标、核心方法、关键结果和整体收获；“5.2 讨论”按顶会/顶刊实验讨论风格写清局限性与优化空间、应用方向、未来研究方向。
- 讨论必须结合本实验真实结果，不写空泛套话，不强行拔高 novelty。
- 若使用官方数据集采样子集，必须写清数据源、采样规模、随机种子、训练/验证/测试划分和可复现限制；不得把采样子集描述成完整数据集，也不得把 synthetic sanity check 写成正式实验。
- 参考文献必须严格另起一页，且只出现一个“参考文献”标题；使用 `\experimentsectionpage{参考文献}` 后应重定义 `thebibliography`，移除默认居中标题。
- 实验原理涉及网络结构、注意力、CNN/RNN/LSTM、语义分割、图像解释等视觉概念时，必须配一张原理图或结构图。
- 实验算法设计必须有流程图或结构图，且正文要先解释图的作用再给出图。
- 图编号按实验章节重置，例如 `图2.1`、`图3.1`；表格编号按全文顺序，例如 `表1`、`表2`。
- 图片必须居中，图注贴近图片；正文、图片、图注之间不得出现异常大空白。
- 正式报告优先引用 PDF 矢量图；保留 SVG 用于编辑检查，PNG 用于快速预览和 PPT 复用。
- LaTeX 必须用 XeLaTeX 成功编译，日志不得有 `! LaTeX Error`、`Undefined control sequence`、未定义引用或 `Overfull`。

## 流程图与系统框图标准

流程图、模型结构图、系统框图必须采用统一学术图风格：

- 白色或极浅背景。
- pastel 低饱和色块。
- 浅灰细边框和细连接线。
- 圆角要克制，不能做成夸张卡片风。
- 连接线必须横平竖直，使用直角折线；不得使用弯曲线、随意斜线。
- 连接线不得穿过框体、文字、公式、图注或编号。
- 若连接线与元素框重合或过近，优先在源图中横向加宽画布、拉开列间距、改走空白通道；不得靠把 LaTeX 插图宽度设到正文页边距之外来“解决”。
- 框内文字必须完整落在框内；必要时缩短文案、手动换行、增大框体或降低字号。
- 避免把流程图做成简单编号卡片堆叠；优先使用“数据准备 / 训练闭环 / 评估归档”等清晰分区，复杂实验可使用反馈回路。
- 导出时必须使用 tight bounding box 或等价裁剪，去掉多余白边。
- 报告、PPT 共用同一套图像资产；重绘报告流程图后，必须同步替换 PPT 中已嵌入的旧图。
- 宽流程图或复杂模型结构图在 PDF 中不得被压得过小；必要时单独成页并使用 `0.95\textwidth` 到 `0.98\textwidth`，但不得超过正文左右页边距。

## PPT 标准

实验 PPT 默认 10 页：

1. 封面
2. 实验概述
3. 理论原理
4. 算法设计与流程
5. 实验设置
6. 实验结果
7. 结果分析
8. 总结与讨论
9. 总结
10. 感谢页

要求：

- 第 8 页来自报告“五、总结与讨论”中的讨论内容，不是强行新增无关内容。
- 第 9 页只做总结，不放“感谢聆听”等结束语。
- 第 10 页单独放“感谢聆听 / 敬请批评指正”等结束信息。
- 流程图、结构图、训练曲线必须作为主视觉呈现，不能缩成不可读小图。
- PPT 中的流程图风格必须与报告一致；报告图更新后，PPT 第 4 页等相关页必须同步替换嵌入图。
- PPTX 必须能被 PowerPoint 打开且不触发修复弹窗；应检查 zip package 无坏文件、无重复 slide part、无缺失媒体。
- 生成后只保留最新版 `.pptx` 与 `_svg.pptx`。

## 最终验证清单

交付前必须完成：

- 读取 LaTeX 日志，确认报告编译页数和错误状态。
- 渲染报告中关键图页：实验原理图、算法流程图、模型结构图、主要结果图。
- 抽取或预览 PPT 中关键图片页，尤其是算法流程页和总结/感谢页。
- 核对报告、README 和 PPT 的数据集口径一致；不得残留旧数据集、旧指标、旧训练轮数或旧结论。
- 草稿阶段对 `实验报告/实验N/`、`PPT/实验N/`、`code/workN code/` 做完整性检查，并明确说明尚未同步 `项目提交/`。
- 用户确认进入最终提交后，对源目录与 `项目提交/` 中的 `.tex`、`.pdf`、`figures/`、PPTX 做 SHA256 hash 一致性检查。
- 用户确认进入最终提交后，打开 `项目提交.zip` 条目，确认新版报告、figures、PPT 已进入压缩包。
- 最终回复必须说明修改了哪些实验、哪些文件、编译/检查结果、是否已同步 `项目提交/` 和 zip、是否仍有风险。

## 不可交付情形

出现以下任一情况，不得声明完成：

- 用户已确认进入最终提交，但 `项目提交/` 或 `项目提交.zip` 仍是旧版本。
- 未获用户审核确认前，提前把草稿实验写入 `项目提交/` 或刷新最终 zip。
- 图中存在文字越框、连接线穿框、弯曲线、斜线、图片不居中或明显大白边。
- PPT 打开需要修复。
- PPT 总结页和感谢页混在一起。
- “五、总结与讨论”缺失，或 `5.1 实验总结` / `5.2 讨论` 篇幅明显失衡，或讨论部分是空泛套话。
- 报告日志有 LaTeX Error、未定义引用或 Overfull。
