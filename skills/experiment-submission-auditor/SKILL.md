# 实验提交审查器

## 使用时机

在 Phase 7 报告复核后、Phase 8 PPT 复核后、或任何整理 `项目提交/` 的任务结束前使用。本 skill 是最终交付门槛，不负责重写正文；发现问题必须返回对应阶段修复。

## 必查目录

- 源报告：`实验报告/实验N/`
- 源 PPT：`PPT/实验N/`
- 源代码：`code/workN code/`
- 提交目录：`项目提交/实验N/`
- 压缩包：`项目提交.zip`

## 报告硬性检查

- `项目提交/实验N/实验报告/实验N报告.tex`、`.pdf`、`figures/` 必须与 `实验报告/实验N/` 中的最新版一致。
- 复制 `figures/` 时逐文件枚举复制，复制后对 `.tex`、`.pdf` 和所有图文件做 SHA256 hash 一致性检查。
- 运行或读取最新 XeLaTeX 日志，确认无 `! LaTeX Error`、`Undefined control sequence`、未定义引用、`Overfull`。
- 渲染提交版 PDF 的关键页面做视觉抽检，不能只检查 `.tex` 中是否存在 `includegraphics`。
- 图像必须居中，图注紧贴图片，正文、图片、图注之间不得出现异常大空白。
- 实验原理部分如涉及网络结构、注意力、CNN/RNN/LSTM、语义分割、图像解释等视觉概念，必须配对应图像。
- 算法流程图、系统框图、模型结构图必须使用横平竖直连接线，不得弯曲、斜穿或覆盖节点。
- 框内文字必须完整落在框内，不得越界、贴边、压线。
- 图编号按实验章节重置为 `图2.1`、`图3.1`；表格按全文顺序为 `表1`、`表2`。
- 必须包含“五、总结与讨论”，并拆分为 `5.1 实验总结` 与 `5.2 讨论`；总结与讨论篇幅应基本相当，讨论需具体覆盖局限性与优化空间、应用方向、未来研究方向，不得只写空泛套话。

## PPT 硬性检查

- 每个实验 PPT 目录只保留最新版 `.pptx` 和 `_svg.pptx`；删除冗余或旧版 PPTX。
- PPTX 必须能被 PowerPoint 打开且不触发修复弹窗；必要时检查 zip package 中是否有重复 slide part、坏 rels 或缺失媒体。
- 总结页不得挤入“感谢聆听”等结束语；结束语应单独作为最后一页。
- 新增页必须来自报告中的“五、总结与讨论”或真实实验证据，不能强行塞入无关内容。
- 框图风格应与报告一致：白底、pastel 色块、细灰线、直角连接、无文字越界。

## 压缩包检查

刷新 `项目提交.zip` 后必须打开压缩包条目核验：

- 每个实验存在 `实验代码/`、`实验报告/`、`实验PPT/`。
- 报告 `.tex`、`.pdf`、`figures/` 中的新增原理图和模型结构图已进入 zip。
- PPT 只包含最新版 `.pptx` 和 `_svg.pptx`。
- 抽查 zip 中关键文件大小和修改时间，避免压缩包仍保留旧文件。

## 交付结论

最终答复必须明确列出：

- 已修改的实验编号和关键文件。
- 报告编译页数与日志检查结果。
- 视觉抽检的 PDF 页或 PPT 页。
- 源目录、提交目录、压缩包是否已同步。
- 未完成或仍有风险的事项。
